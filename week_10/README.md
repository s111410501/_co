## 一、作業說明

nand2tetris 的 Hack 電腦只能執行 16-bit 的機器碼，但直接寫機器碼既困難又容易出錯。因此需要一個**組譯器（Assembler）**，把人類可讀的 Hack 組合語言（`.asm`）自動轉換成機器碼（`.hack`）。

本作業即實作 Project 6 的組譯器，程式為 [`assembler.py`](./assembler.py)，可讀取 `.asm` 檔並輸出對應的 `.hack` 檔。

### 作業要求

1. 正確翻譯 **A-指令** 與 **C-指令**。
2. 支援 **符號（symbol）**：
   - 預先定義符號：`R0`～`R15`、`SP`、`LCL`、`ARG`、`THIS`、`THAT`、`SCREEN`、`KBD`。
   - 標籤：`(LABEL)`，需解析成對應的 ROM 行號。
   - 變數：未定義的符號自動從位址 16 開始配置。
3. 忽略註解（`//`）與空白。
4. 能通過 nand2tetris 官方提供的測試程式。

## 二、Hack 組合語言規格

### 2.1 A-指令

格式：`@value`

- 將 15-bit 的 `value` 載入 A 暫存器。
- 機器碼格式：`0` + 15-bit 二進位值。

```asm
@2      → 0000000000000010
@sum    → 0000000000010000   （變數由位址 16 開始配置）
```

### 2.2 C-指令

格式：`dest=comp;jump`（`dest=` 與 `;jump` 可省略）

- 機器碼格式：`111` + `comp`(7 bits) + `dest`(3 bits) + `jump`(3 bits)。

```asm
D=D+A   → 111 0000010 001 000
        = 1110000010010000
0;JMP   → 111 0101010 000 111
        = 1110101010000111
```

### 2.3 符號處理

| 符號類型 | 例子 | 位址來源 |
|----------|------|----------|
| 預先定義 | `R5`、`SCREEN` | 固定值 |
| 標籤 | `(LOOP)` | 該標籤後第一道指令的 ROM 行號 |
| 變數 | `@sum` | 從 16 開始依序配置 |

## 三、實作方式

### 3.1 組譯流程

```text
讀取 .asm
   │
   ▼
清除註解與空白
   │
   ▼
Pass 1：掃描 (LABEL)，記錄其 ROM 行號
   │
   ▼
Pass 2：翻譯 A-指令 / C-指令
        並為未定義變數配置位址（從 16 開始）
   │
   ▼
輸出 .hack（每行 16-bit 二進位）
```

採用 **兩階段（Two-pass）** 的原因是：標籤可能在使用之後才定義，必須先掃描一輪建立完整符號表，第二輪才能正確解析。

### 3.2 核心資料表

- `COMP_TABLE`：28 種 `comp` 組合對應的 7-bit 控制位元。
- `JUMP_TABLE`：8 種 `jump` 條件對應的 3-bit 控制位元。
- `dest`：依 `A`、`D`、`M` 是否出現，分別產生 3-bit 控制位元。

### 3.3 程式結構

| 函式 | 用途 |
|------|------|
| `assemble_lines(raw_lines)` | 將組合語言字串列表轉譯為機器碼列表 |
| `assemble_file(filepath)` | 讀取 `.asm`、輸出 `.hack` 並印出結果 |

## 四、使用方式

### 4.1 組譯檔案

```bash
python assembler.py <file1.asm> [file2.asm ...]
```

輸出檔與輸入檔同名，副檔名改為 `.hack`：

```bash
python assembler.py Add.asm
# 組譯完成：Add.hack (共 6 行機器碼)
```

### 4.2 執行內建範例

不帶參數時，會執行內建範例（計算 `2 + 3` 並存入變數 `sum`）：

```bash
python assembler.py
```

```text
--- 執行內建測試範例 ---
@2         -> 0000000000000010
D=A        -> 1110110000010000
@3         -> 0000000000000011
D=D+A      -> 1110000010010000
@sum       -> 0000000000010000
M=D        -> 1110001100001000
(END)      -> (標籤不佔位)
@END       -> 0000000000000110
0;JMP      -> 1110101010000111
```

## 六、限制

- 未處理 `dest`／`comp`／`jump` 的語法錯誤，遇到未知符號會直接拋出 `KeyError`。
- 僅支援標準 Hack 組合語言，不含巨集或額外語法。
- 變數位址從 16 開始配置，未檢查是否與位址 ≥ 16 的既有標籤衝突（官方測試程式無此情況）。

## 七、心得

這次作業讓我實際體會到「組譯器就是一個小型的編譯器」：第一階段建立符號表對應編譯器的語法分析，第二階段產生機器碼對應程式碼產生。最關鍵的是理解為何需要兩階段——因為標籤可以先使用後定義。透過與官方組譯器逐行比對，也驗證了自己的實作在真實的大型程式（Pong）上仍然正確。
